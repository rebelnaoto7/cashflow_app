# 開発者向けメモ（cashflow_app）

[README](../README.md) を補足する、開発者向けの情報です。

## Streamlit 版との対応

このアプリは、Streamlit で作った資金繰りアプリを Django に移植したものです（Streamlit 版の `app.py` はこのリポジトリには含まれていません）。計算ロジックは関数名を保ったまま `dashboard/services.py` に移し、画面を Django テンプレート、Bootstrap 5、Plotly.js に置き換えています。

| Streamlit 版 | Django 版 | 場所 |
| --- | --- | --- |
| `st.session_state` | Django のセッション（キー `cf_state` と `cf_actual`） | `dashboard/views.py` |
| `init_state()` の既定値 | `DEFAULTS`・`ACTUAL_DEFAULT` | `dashboard/constants.py` |
| サイドバーの入力欄 | `AssumptionsForm` | `dashboard/forms.py` |
| `st.tabs`（5 タブ） | 1 ページと Bootstrap のタブ | `dashboard/templates/dashboard/index.html` |
| `compute_plan` などの計算関数 | 同じ名前の関数（pandas・NumPy） | `dashboard/services.py` |
| `st.data_editor`（実績の編集） | 入力欄を並べた HTML の表（`actual_{行}_{列}`） | `index.html` の実績入力タブ |
| Plotly のグラフ | ビューで図の dict を作り、Plotly.js（CDN）で描画 | `views.py` の `_build_figures` |
| `st.download_button`（Excel） | ダウンロード用のビュー | `views.py` の `download_excel` |
| Styler による色分け | CSS クラス | `dashboard/templates/dashboard/base.html` |

## リクエストの流れ

1. `GET /`：セッションの前提条件（なければ既定値）で計算し、画面を表示します。
2. `POST /`：前提条件フォーム・実績入力表・表示月をまとめて受け取り、セッションに保存してから計算し、同じ画面を返します。
   - 前提条件フォームが不正な場合は、前提条件だけ前の値のまま使います。実績入力表は保存します。
   - 実績入力表で数値にできない値は、前の値のまま使います。
3. `GET /reset/`：セッションの `cf_state` と `cf_actual` を消して `/` へリダイレクトします。
4. `GET /download/excel/`：セッションの値で計算し、`export_to_excel` で作った .xlsx を返します。

## 計算式

内部の金額はすべて千円です。月は「当月・1ヶ月後・2ヶ月後・3ヶ月後」の 4 ヶ月で、売上・仕入・設備投資は「前々月・前月」を含めた 6 ヶ月分を持ちます（設備投資の前々月・前月の値は、どの計算にも使われません）。

### 月次資金繰り表（`compute_plan`）

| 項目 | 計算 |
| --- | --- |
| 現金売上 | その月の売上 × 当月現金売上比率 |
| 売掛金回収（前月分） | 前月の売上 × 翌月入金比率 |
| 売掛金回収（前々月分） | 前々月の売上 × 翌々月入金比率 |
| 営業収入合計（A） | 上の 3 項目の合計 |
| 現金仕入 | その月の仕入 × 当月現金仕入比率 |
| 買掛金支払（前月分） | 前月の仕入 × 翌月支払比率 |
| 買掛金支払（前々月分） | 前々月の仕入 × 翌々月支払比率 |
| 固定費合計 | 人件費＋家賃＋水道光熱費＋通信費＋その他経費＋税金支払（毎月同じ額） |
| 営業支出合計（B） | 仕入関連の 3 項目＋固定費合計 |
| 営業収支差額（A－B） | A − B |
| 財務収支合計（C） | 月次新規借入 − 月次返済 − 月次利息（借入金残高 × 年利率 ÷ 12） |
| 投資収支合計（D） | −（その月の設備投資） |
| 当月収支合計 | （A − B）＋ C ＋ D |
| 翌月繰越現金 | 前月繰越現金＋当月収支合計（最初の月の前月繰越現金は期首現金残高） |

- 月次利息は、入力した借入金残高から毎月同じ額を計算します。返済による残高の減少は反映しません。
- 「合計」列は 4 ヶ月分の合計です。前月繰越現金と翌月繰越現金の合計は空欄にしています。

### KPI（ダッシュボード）

| KPI | 計算 | 下段の差分 |
| --- | --- | --- |
| 当月末残高 | 当月の翌月繰越現金 | 期首現金残高との差 |
| 3ヶ月後残高 | 3ヶ月後の翌月繰越現金 | 期首現金残高との差 |
| 期間中最低 | 期首現金残高と各月末残高のうち最も小さい値 | 最低必要残高との差 |
| 営業CF合計 | 4 ヶ月分の営業収支差額（A－B）の合計 | なし |

### 実績（`compute_actual`）

実績入力表の 9 項目から、営業収入合計（A）・営業支出合計（B）・営業収支差額・当月収支合計・翌月繰越現金を、計画と同じ形で集計します。財務収支合計（C）と投資収支合計（D）は入力値をそのまま使い、残高は期首現金残高から積み上げます。

### シナリオ（`compute_scenario`）

```text
月末残高 = 前月末残高
         + 売上 × 売上係数 − 仕入 × 仕入係数 − 固定費合計 × 固定費係数
         − 月次返済 − 月次利息 − 設備投資
         − 一時損失（悲観のみ、2ヶ月後に 2,000 千円）
         + 新規借入（悲観のみ、1ヶ月後に 3,000 千円）
```

係数は README の「シナリオの前提」を参照してください。売上と仕入はその月に全額入金・支払されるものとして扱い、回収・支払サイトと前提条件の「月次新規借入」は使いません。

### 予実差異（`evaluate_variance`）

差異率 ＝（実績 − 計画）÷ |計画|（計画が 0 なら 0）です。収入型の項目は 0% 以上で ○良好、−10% より大きければ △要確認、それ以外は ×悪化です。支出型（営業支出合計）は符号を反対にして同じ基準で判定します。

## 既知の不具合の該当箇所

README の「既知の制限」に挙げた不具合の場所です。

| 内容 | 場所 |
| --- | --- |
| 現金残高推移グラフの単位の混在（棒と数値ラベルは万円、縦軸の表記と最低必要残高の線は千円） | `dashboard/views.py` の `_build_figures`（Tab1-1 の図） |
| 実績入力表の見出しが「万円」（値は千円） | `dashboard/templates/dashboard/index.html` の実績入力タブの見出し |
| 評価セルに色が付かない（Bootstrap 5.3 の `.table` のセルのスタイルが優先される） | `dashboard/templates/dashboard/base.html` の `.eval-good`・`.eval-warn`・`.eval-bad` |
| 送信後に常にダッシュボードタブへ戻る・再読み込みでフォームが再送信される（POST のあとにリダイレクトしていない） | `dashboard/views.py` の `index` |
| 再計算後に「-0.0」と表示される（フォーム経由の設備投資 0.0 が `-capex` で −0.0 になる） | `dashboard/services.py` の `compute_plan` と `views.py` の `_man` |
| Excel に単位や書式がない | `dashboard/services.py` の `export_to_excel` |

## 動作確認の手順

自動テストはまだないため、変更したときは次の手順で確認します。

```powershell
python manage.py check
python manage.py runserver
```

1. <http://127.0.0.1:8000/> を開き、5 つのタブ・KPI・3 つのグラフが表示されることを確認します。
2. 前提条件を変えて「再計算する」を押し、KPI と表が変わることを確認します。
3. 実績入力表の値を変えて「実績を反映して再計算」を押し、予実差異表が変わることを確認します。
4. 「ダウンロード」タブから .xlsx を保存し、2 つのシートの値（千円）が画面の値（万円）と一致することを確認します。
5. 「既定値に戻す」でサンプル値に戻ることを確認します。
